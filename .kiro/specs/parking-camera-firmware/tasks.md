# Implementation Plan

- [x] 1. 基盤: ビルド構成と設定
- [x] 1.1 実機向けとホスト向けのビルド環境を用意する
  - 実機向けの環境に、ESP32-CAMのボード、シリアル速度115200bps、PSRAMとArduinoのログをエラーだけにするビルドフラグを設定する
  - ファームウェアの版を`git describe --always --dirty`の結果からビルド時に埋め込み、得られないときは`unknown`にする
  - ホスト向けの環境に、Unityでの単体テストと、ハードウェアに依存しないロジックのライブラリを読み込む設定を入れる
  - 空の起動処理とループで、実機向けのビルドが通り、ホスト向けのテストの実行が(テスト0件で)エラーなく終わる
  - _Requirements: 3.7, 4.2_

- [x] 1.2 設定値の検証ロジックを作る
  - 空でない文字列、`https://`で始まりホスト名があるURL、60〜3600秒で1時間を割り切る撮影間隔、0時からの分で開始が終了より前かつ1439以下の監視時間、-2〜2の露出補正を、コンパイル時に評価できる判定として用意する
  - Arduino・ESP-IDFのヘッダーを読み込まず、C++標準ライブラリだけに依存させる
  - URL・撮影間隔・監視時間・露出補正の受け付けと拒否の境界値を確かめる単体テストが、ホスト向けの環境で通る
  - _Requirements: 4.3, 4.4, 4.13, 5.4_

- [x] 1.3 書込み時の設定を1箇所に集め、雛形を用意する
  - 送信先URL、デバイス用トークン、WiFiの接続方式(PSK、PEAP、TTLS)と接続情報、802.1XのID・ユーザー名・パスワード・CA証明書、撮影間隔、監視時間、上下反転・左右反転、露出補正の既定値を、実値のファイルから読み込む
  - 与えられていない値は既定値(撮影間隔300秒、監視時間9:00〜17:30、反転なし、露出補正0、IDは空)で補い、必須値の欠け・不正値はビルド時に止める。接続方式に応じて、PSKならパスワード、802.1Xならユーザー名とパスワードを必須にする
  - 全項目を値を伏せて並べた雛形をコミット対象にし、実値のファイルはGitの追跡対象から外す。雛形の802.1XのCA証明書の欄はGunetEAP用のルートCAを指す
  - 雛形を写して値を入れた設定ではビルドが通り、必須値を消す、撮影間隔を59や7にする、監視時間の開始を終了より後にする、URLを`http://`にする、のいずれでもビルドが止まる。`git status`に実値のファイルが現れない
  - _Requirements: 1.2, 2.1, 2.2, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.12, 4.13, 5.1, 5.2, 5.4_

- [x] 1.4 (P) 信頼するルートCAの証明書を用意する
  - 送信先の検証用に、ISRG Root X1・ISRG Root X2・GTS Root R1・GTS Root R4・SSL.com Root Certification Authority ECC・SSL.com Root Certification Authority RSAのPEMを連結した1つの文字列を用意する
  - GunetEAPの認証サーバーの検証用に、SECOM TLS RSA Root CA 2024(自己署名版)のPEMを用意する
  - どちらも公開情報としてコミットし、ファームウェアから文字列として参照できる
  - _Boundary: ルートCA(cms_root_ca、eap_ca_gunet)_
  - _Requirements: 3.3, 4.10_

- [x] 2. ハードウェア非依存の判断ロジック
- [x] 2.1 (P) 監視時間と撮影の区切りの時刻を計算する
  - 与えた時刻以降で、監視時間内にある最初の区切り(日本時間で撮影間隔の倍数の時刻)を求める。17:30の区切りは含み、それを過ぎたら翌日の開始の区切りを返す
  - 時刻が監視時間内かを判定する
  - 日本時間8:59:59→9:00、9:00:00→9:00、9:02→9:05、17:30:00→17:30、17:30:01→翌日9:00、日付と月末の境、間隔600秒と3600秒の単体テストが通る
  - _Boundary: Schedule_
  - _Requirements: 1.1, 1.3, 1.7_

- [x] 2.2 (P) 受信エンドポイントの応答を分類する
  - 応答コードと本文から、成功、撮影時刻の不正、露出補正の不正、認証失敗、大きすぎる、JPEGでない、サーバーエラー、想定外の応答に分ける
  - 成功の本文から露出補正値を取り出し、-2〜2の整数でないとき・キーが無いとき・本文が読めないときは値なしにする。外部ライブラリを使わない最小の解釈にする
  - `{"exposure":1}`・`{ "exposure" : -2 }`で値あり、`{}`・`{"exposure":3}`・`{"exposure":1.5}`・`{"exposure":null}`・`{"exposure":"1"}`・壊れた本文で値なし、400の2種類の区別、401・413・415・500・302の分類の単体テストが通る
  - _Boundary: IngestResponse_
  - _Requirements: 3.5, 8.1, 8.2, 8.3, 8.4, 9.4_

- [x] 2.3 (P) HTTPの`Date`ヘッダーを時刻に変換する
  - IMF-fixdate形式の文字列をUnix秒に変換し、読めない文字列は失敗を返す
  - 正しい値、閏年の2月29日、壊れた文字列の単体テストが通る
  - _Boundary: HttpDate_
  - _Requirements: 9.1_

- [x] 2.4 (P) 連続失敗の計数と再起動の判断を作る
  - 撮影を試みた周期の失敗を数え、6回連続で再起動すべきと判断し、成功で0に戻す
  - 5回までは再起動しない、6回目で再起動する、成功で0に戻る、の単体テストが通る
  - _Boundary: FailurePolicy_
  - _Requirements: 6.7_

- [x] 3. 端末のハードウェアと通信
- [x] 3.1 (P) カメラの初期化と撮影を作る
  - AI Thinkerのピン配置、UXGAのJPEG、`jpeg_quality=10`、フレームバッファ1枚をPSRAMに置く設定で初期化し、AWB自動・レンズ補正有効・露出補正・上下反転・左右反転を一度だけ設定する
  - 初期化後は2秒待ってから5フレームを100ms間隔で捨てる。撮影のたびに3フレームを捨て、取得を500ms待ちで最大20回試す。取れないときと1MiBを超えたときは撮影失敗を返す
  - 露出補正を後から変えられるようにする
  - 初期化の成否とセンサーのPID、撮影した画像のバイト数をシリアルに出力し、実機向けのビルドが通る
  - _Boundary: Camera_
  - _Requirements: 1.4, 1.5, 1.6, 2.1, 2.3, 7.1, 7.2, 8.1, 8.6_

- [x] 3.2 (P) WiFiの接続方式ごとの接続を作る
  - 接続情報をNVSに書かず、STAモードで自動再接続を有効にする
  - PSKはSSIDとパスワードで接続する。802.1Xは試行のたびに前回の認証情報とCA証明書を消してから、CA証明書を終端のNULを含む長さで設定し、TTLSのときは内部認証をMSCHAPv2にし、IDが空ならユーザー名をIDに使って接続する
  - 1回の試行を15秒で打ち切り、切断して1回だけ試し直し、合計30秒で失敗を返す。接続済みならすぐ成功を返す
  - SSIDと接続方式、接続後のIPとRSSIをシリアルに出し、パスワード・ID・ユーザー名は出さない。CA証明書が未設定なら起動時と接続のたびに警告を出す
  - 実機向けのビルドが、PSK・PEAP・TTLSのそれぞれの設定で通る
  - _Boundary: WifiLink_
  - _Requirements: 4.6, 4.7, 4.8, 4.9, 4.10, 4.11, 5.3, 6.1, 6.3, 7.1_

- [x] 3.3 (P) 端末の時刻合わせを作る
  - WiFi接続の後に、`ntp.nict.jp`・`time.cloudflare.com`・`pool.ntp.org`へのSNTPを1時間周期で始め、同期完了の通知で同期済みにする
  - 未同期ならSNTPを最大30秒待ち、合わなければ送信先と同じホストへHTTPSで`GET /`を送り、応答コードに関わらず`Date`ヘッダーで時刻を設定する。TLSは送信先と同じルートCAとホスト名で検証する
  - 撮影時刻の不正を受けたときに、SNTPを始め直して未同期に戻せるようにする
  - 同期の成否と時刻の出どころ(SNTPか`Date`か)をシリアルに出し、実機向けのビルドが通る
  - _Boundary: ClockSync_
  - _Depends: 1.4, 2.3_
  - _Requirements: 9.1, 9.2, 9.3, 9.4, 7.1_

- [x] 3.4 (P) 画像の送信を作る
  - 送信先URLがHTTPSでなければトークンを送らずに拒否し、そのことをシリアルに出す
  - 送信先のルートCAとホスト名を検証するTLSで、JPEGを本文にPOSTし、Bearerのデバイス用トークン、露出補正値、撮影時刻、端末の状態(RSSI、起動からの秒数、直前の再起動の理由、直前まで続いた失敗の回数、ファームウェアの版)をヘッダーに付ける。証明書の検証を無効にした接続は使わない
  - 接続10秒、ハンドシェイク15秒、やり取り20秒で打ち切り、接続を再利用しない。成功以外の本文は最大256バイトだけ読み、応答を分類した結果を返す
  - 送信の成否(失敗の種類と応答コード)とRSSIと所要時間をシリアルに出し、トークンは出さない。実機向けのビルドが通る
  - _Boundary: Uploader_
  - _Depends: 1.2, 1.4, 2.2_
  - _Requirements: 3.1, 3.2, 3.3, 3.5, 3.6, 3.7, 5.3, 5.4, 6.3, 7.2_

- [x] 4. 周期の制御と回復の統合
- [x] 4.1 起動処理とウォッチドッグを組み立てる
  - 起動時に直前の再起動の理由を英字でシリアルに出し、送信用に保持する
  - ウォッチドッグを90秒で設定し、ループのタスクを登録する
  - カメラの初期化に失敗したら理由を出して10秒後に再起動する。成功したらWiFiの接続と時刻合わせを始める
  - 書き込んだ端末が、人の操作なしに起動からWiFi接続・時刻合わせまで進み、各段階の成否がシリアルに出る
  - _Depends: 3.1, 3.2, 3.3_
  - _Requirements: 6.4, 6.5, 6.6, 7.1, 7.3, 9.1_

- [x] 4.2 撮影と送信の周期を組み立てる
  - 1秒ごとにウォッチドッグを給餌しながら待ち、WiFiが切れていれば再接続を試みる(失敗したら60秒あけて再試行)。時刻が一度も合っていない間は撮影せず、60秒ごとに時刻合わせを試み、未同期であることを出す
  - 時刻が合った時点で監視時間内なら区切りを待たずに1枚目を撮り、以降は区切りの時刻に撮る。撮影後は直前の区切りの次から次の区切りを求め、送信が長引いて過ぎた区切りは飛ばす。次の区切りと監視時間外であることをシリアルに出す
  - 撮影に成功したら、その1枚だけを撮影時刻・露出補正値・端末の状態を付けて送る。撮影に失敗したらその周期は送らない
  - 成功の応答に露出補正値があればすぐカメラに反映し、次の撮影から使う。受け取った値は保存せず、再起動後は書込み時の既定値に戻る
  - 実機で、監視時間内は区切りごとに撮影・送信が1回ずつ行われ、監視時間外は撮影せずに待つ
  - _Depends: 2.1, 3.4_
  - _Requirements: 1.1, 1.3, 1.6, 1.7, 3.4, 3.6, 3.7, 6.1, 8.1, 8.4, 8.5, 9.2, 9.3_

- [x] 4.3 失敗からの回復を組み立てる
  - 撮影と送信の失敗を連続失敗として数え、成功で0に戻す。監視時間外と時刻が合うまでの待ちは数えない。6回連続で回復のための再起動をすることをシリアルに出して再起動する
  - 失敗した画像は再送せず、次の区切りで新しく撮った画像を送る
  - 撮影時刻の不正を理由に拒否されたら時刻を未同期にし、次の撮影の前に合わせ直す
  - 各段階の前後でウォッチドッグを給餌し、上限時間内に戻らないときだけ90秒で再起動する
  - 送信先を止めた状態でも端末が止まらずに区切りごとの試行を続け、6回目の失敗で再起動して周期を再開する
  - _Depends: 2.4_
  - _Requirements: 6.2, 6.3, 6.4, 6.6, 6.7, 9.4_

- [x] 4.4 設定の書き方と書込み・設置前の確認の手順を書く
  - 雛形から実値のファイルを作る手順、接続方式ごとの設定項目、別の設置先で802.1Xの認証サーバーのルートCAを確かめて取得する手順、書込みとシリアルモニタのコマンド、設置前の確認項目を記す
  - 実値のファイルをコミットしないこと、端末を紛失したときと開催後の大学アカウントのパスワード変更とトークンの無効化を記す
  - 手順どおりに雛形を写して値を入れると、実機向けのビルドと書込みができる
  - _Requirements: 4.1, 4.2, 5.1, 5.2_

- [x] 5. 実機の確認(設置前)
- [x] 5.1 受信側に依存しない動作を実機で確かめる
  - 802.1Xで、GunetEAP用のCA証明書を与えた接続が成立し、別のCAのPEMを与えると接続しない
  - 時刻が合うまで撮影せず、合ったあとに監視時間外なら撮影しないことを、シリアル出力で確かめる
  - ループに意図的な無限ループを入れた検証用ビルドで、90秒後に再起動理由`TASK_WDT`で再起動する。検証用の変更はコミットしない
  - シリアル出力にトークン、WiFiのパスワード、802.1XのIDとユーザー名とパスワードが出ていない
  - 確かめに使う実値の設定はGitの追跡対象外のファイルにだけ置く
  - _Requirements: 4.10, 5.3, 6.4, 7.1, 7.3, 9.2_

- [x] 5.2 本番の受信エンドポイントへの送信を実機で確かめる
  - 受信側(`aramakisai-web`の`parking-camera-endpoint`の受信エンドポイント)が本番に反映され、この端末用のデバイス用トークンが発行された後に行う
  - 本番の受信エンドポイントへ送り、200と露出補正値が返る。撮影時刻がCMSの受信時刻と数秒以内で一致する
  - 監視時間の開始を現在時刻の数分後にして、開始前は撮影せず、開始の区切りで1枚目を送る
  - 誤ったトークンで401が出力され、次の区切りで再試行する
  - WiFiのアクセスポイントを止めて戻すと、次の区切りまでに再接続して送信が戻る
  - _Depends: 4.3_
  - _Requirements: 1.1, 3.1, 3.2, 3.3, 3.5, 3.6, 3.7, 6.1, 6.2, 7.2, 8.1_
